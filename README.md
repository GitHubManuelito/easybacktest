# EasyBacktest

A local, data-first backtester inspired by NautilusTrader's event-driven simulation model. It runs a PowerLanguage/EasyLanguage strategy file against **NQ, ES, GC, BTC, MNQ, MES, MGC, CL, and ZN**.

## Imported market data (2026-10-30)

The six named ZIP batches and the subsequently completed `Non confermato 801024.crdownload` ZIP are preserved under `data/imported_20261030/`; the engine converts data lazily and caches derived bars in that folder. The imported inventory is recorded in `IMPORT_STATUS.md` and the supplemental batch in `archive_801024_manifest.csv`. TBBO feeds provide executed trade OHLCV, trade counts, bid/ask and displayed sizes, uptick/downtick counts, aggressor buy/sell volume and delta, plus counts of no-quote, crossed, locked, off-tick, outside-quote (sweep) and wide-spread records. TBBO filtering keeps front-contract, non-bad-tick records and retains repeated fills.

NQ also has MBP-10 summary features for 63 sessions: midpoint OHLC/change, update/add/cancel/modify and side counts, spread, microprice, top imbalance, depth-5/depth-10 and book-pressure measures. The delivered summary file has a session date but no within-session timestamp, so the engine preserves it but does not attach its rows to minute bars or claim synchronized MBP-10 results. Timestamped local NQ order events remain available to order-book strategies. MGC has five days of BBO and L2 event data, in January–February 2026; they do not overlap the existing MGC trade series. MGC book strategies therefore use the BBO midpoint as an explicitly labeled price proxy, operation counts by side and level, and zero volume. Results from that five-day source are not trade-OHLCV backtests.

Imported trade-bar caches are built per contract: MNQ, MES, CL and ZN use uploaded TBBO as their available primary data; NQ flow strategies use uploaded NQ TBBO, while NQ book strategies use timestamped local NQ order events. NQT_BTIC is a basis-differential feed, not an outright NQ price series, so it is intentionally not offered as a normal asset. SPXW and NQ options are retained in the archive; this bundle has no overlapping NQ underlying bars for the July–September 2026 options sample, and SPXW lacks underlying SPX OHLCV, so they are not presented as executable option backtests.

Feature columns can be referenced directly by name in PowerLanguage expressions (for example, `flow_delta`, `mbo_depth_imbalance_5`, `mbo_add_bid_count`, or `feed_wide_spread_count`). Only fields actually present in the selected feed can be used. The engine does not claim full MultiCharts equivalence: chart drawing, external DLLs, broker routing, portfolio/multi-symbol execution, and live DOM replay are outside this single-instrument OHLCV/feature backtester. See `data/imported_20261030/REVIEW.md` for source quality and missing-session notes.

## Quick start

1. Install Python 3.10+ and dependencies: `python -m pip install -r requirements.txt`.
2. Put minute bars in `data/<ASSET>.csv` or `.parquet`; CSV.GZ is accepted. Required fields are timestamp, open, high, low, close; volume is optional. Raw Databento TBBO files in `data/raw/tbbo` are converted to cached 1-minute bars on first use. Timestamp may be one field, or separate `Date`/`Time` columns. The parser accepts common `YYYYMMDD` + `HHMMSS` and `MM/DD/YYYY` + `HH:MM` formats. Naive timestamps default to UTC unless the selected source or `ENGINE_DATA_TIMEZONE` sets another zone.
3. Put your PowerLanguage strategy in a `.pl` file in this folder or provide its full path when prompted.
4. Run `python run_backtest.py`. It asks which asset(s) to test, how much history to use (`4y`, `18mo`, `90d`, or `all`), the strategy, Data1 timeframe, entry `NumContracts`, and LucidFlex/LucidPro account settings. The same options can be supplied with `--asset`, `--data-period`, `--strategy`, `--bar-timeframe`, `--num-contracts`, `--lucidflex-account`, `--lucidpro-account`, and `--lucidpro-dll`. Strategy markers supply timeframe, timezone, and session defaults. The runner prints load status and periodic bar/Monte Carlo progress.

Strategies marked `ENGINE_DATA2_EXTERNAL_REQUIRED=true` need a separate OHLCV file for Data2. Supply it with `--data2 path/to/iv.csv` (or an asset-keyed folder when testing multiple assets). Data2 is aligned at completed bar boundaries to avoid looking ahead. For `ZVRPContrarianTrend.pl`, Data2 is an implied-volatility index (VXN for NQ, GVZ for GC, or a suitable BTC IV index), not another copy of the traded asset. `Plot1`–`Plot99` and `NoPlot` values are retained in `equity.csv` and rendered to `strategy_plots.png` when present. `SessionEndTime` is inferred from gaps in the selected bar timestamps; use a session-filtered feed when an exact exchange close matters.

## Trading and fill assumptions

The initial engine deliberately uses conservative, explicit defaults: market orders submitted on a bar fill at the next bar's open; one position per instrument; no pyramiding; commissions and slippage are configurable; a final open position is liquidated at the final close. Futures use the configured point value (NQ $20, ES $50, GC $100); BTC defaults to $1 per price unit and a 0.1% notional commission per side. Change these settings in `config.json`. OHLC bars cannot reveal intrabar order sequencing, so stop/limit orders and same-bar ambiguity are not silently guessed.

## PowerLanguage support

The implemented OHLCV indicator names, formulas, common call forms, warm-up behavior, and calculation boundaries are documented in [`INDICATORS.md`](INDICATORS.md). The MultiCharts catalog cross-reference and data-coverage limits are in [`MULTICHARTS_STUDY_SUPPORT.md`](MULTICHARTS_STUDY_SUPPORT.md). `Plot1`–`Plot99` and `NoPlot` are exported to `equity.csv` and `strategy_plots.png`.

The runner accepts raw Databento TBBO `.dbn` as a source. It streams trades into cached 1-minute OHLCV bars and retains the latest trade-time best bid/ask and displayed sizes as `Bid`, `Ask`, `BidSize`, `AskSize`, and `TradeCount`. It derives `UpTicks`/`DownTicks` from consecutive trade-price changes, plus approximate signed trade-volume fields (`flow_buy_volume`, `flow_sell_volume`, `flow_delta`, `flow_delta_pct`, and `flow_imbalance`) from trade prices against the contemporaneous top of book. TBBO is top-of-book; it does not provide full DOM depth. The NQ order-event feed produces per-minute Add/Cancel/Modify/Fill/Trade counts and sizes split by side, signed trade and add/cancel imbalance fields, plus reconstructed best bid/ask and up to ten price levels (`mbo_bid_price_1`/`mbo_bid_size_1` through level 10, and the equivalent ask fields). It also produces five-level depth totals, imbalance, spread, and microprice, as well as tick counts. These snapshots are reconstructed from the supplied order IDs and Add/Modify/Cancel/Fill events; they do not replay queue position or prove a historical limit order would have filled. If a strategy requires `mbo_*`, `flow_*`, tick, or quote fields, the runner prefers the matching richer local feed when one is installed. A requested period longer than that feed's history uses all available feed rows and reports the actual span. `data/manifest.json` records the supplied shared data sources and their import status. CSV.GZ and Parquet are also supported.

The downloaded compact NQ/GC Parquet alternatives are in `data/NQ/ohlcv` and `data/GC/ohlcv`; normal asset selection continues to prefer the longer root CSV histories. The unique NQ London Strategic Edge batch is unpacked as `.csv.gz` files under `data/NQ/raw/orderbook/daily_events`; duplicate ZIP parts and the identical standalone CSV copy are kept separately. Selecting that directory converts `Trade` events into minute OHLCV and adds per-minute action counts/sizes such as `mbo_add_count`, `mbo_cancel_size`, and `mbo_buy_trade_volume`. This is not a reconstructed depth ladder or queue-fill replay.

The runner interprets a practical PowerLanguage subset: `Inputs`/`Vars`/fixed and dynamic `Array` declarations (up to multidimensional indexing), OHLC series defaults such as `Price(Close)`, nested `If/Else`, `Begin/End`, bounded `For ... To/DownTo` and guarded `While ... Begin ... End` loops, arithmetic, boolean/comparison operators, `Crosses Over/Under`, Data1 and one derived Data2 stream (including `Date of Data2` and prior completed Data2 bars), `BarStatus(1/2)`, `Date`/`Time`, `CurrentBar`/`BarNumber`, equity/position fields, `BigPointValue`, OHLCV, trade-derived `UpTicks`/`DownTicks`, and available quote-field history, numeric `liq_*`/`flow_*`/`mbo_*` features, `HighD`/`LowD`, common indicators and math, rolling indicators over derived expressions, lazy `IFF`/`IFFString`, `StDev`/`StdDev`/`StandardDev`, `HighestFC`, variable-series indicators, array indexing/resizing, typed get/set, range fill/copy, and sort helpers, multiline and single-line market/limit/stop orders including `Sell Short`, dollar and point-based `SetStopLoss`, `SetProfitTarget`, `SetBreakEven`, `SetDollarTrailing`, `SetPercentTrailing`, `SetTrailingStop_pt`, and `SetExitOnClose`. Named stop orders receive stop-market gap handling and configured slippage. `MarketPosition[1]` reads the prior bar; `MarketPosition(1)` reads the previous closed trade. Point-based stops use instrument tick size and point value. PowerLanguage `Date`/`Time` refer to bar close timestamps; next-bar market orders fill at the next bar open. Daily Data2 updates only from bars seen so far, preventing future daily-close leakage. `[IntrabarOrderGeneration=False]` is accepted; `True` is rejected because OHLC execution cannot reproduce tick-level IOG.

The runner reads common chart declarations from PowerLanguage header comments: `Recommended chart: 30-min bars`, a daily `Data2:` line, and an `RTH session HHMM-HHMM ET` note set the suggested Data1/Data2 intervals, timezone, and Data1 session filter. The equivalent `ENGINE_BAR_TIMEFRAME`, `ENGINE_DATA2_TIMEFRAME`, `ENGINE_SESSION_TIMEZONE`, `ENGINE_DATA_TIMEZONE`, and `ENGINE_DATA1_SESSION` markers are also supported. Session filtering can be overridden with `--data1-session HHMM-HHMM`. These are data/chart settings; the interpreter does not rewrite a strategy's inputs or rules.

Data2 is resampled from the selected Data1 bars and defaults to five minutes unless a strategy header or `--data2-timeframe` specifies another interval. Its bars use right-closed buckets: a timestamp labels the completed bar. Stop/limit triggers are checked against the primary OHLC bars. When a stop and target are both touched within one bar, the simulator assumes the stop happened first. Stop-market orders include configured slippage; limit fills do not receive adverse slippage.

This is not the proprietary MultiCharts compiler, and a Python interpreter cannot safely promise to run every unmodified script. This engine targets single-instrument historical bar simulation. User-defined functions, portfolio/multi-symbol strategies, tick-by-tick IOG, full historical DOM/L3 queue replay, DLL/external APIs, real-time quotes, and chart UI effects are unsupported. The London Strategic Edge data is summarized to bars, not replayed as individual order-book updates. Unsupported constructs should produce a line-numbered error; visuals do not change orders. PineScript is not executed by this version.

## Metrics

The report includes net/gross profit and loss, return, CAGR, annualized volatility, Sharpe and Sortino ratios, maximum drawdown and duration, Calmar and recovery factors, trade count, win rate, profit factor, payoff ratio, expectancy, average winner/loser and trade, median trade, best/worst trade, longest win/loss streaks, and average holding bars and exposure. Sharpe and Sortino both use daily close-to-close returns and matching annualization; Sortino downside deviation includes every daily period with a 0% minimum acceptable return. Trade returns are also reported as directional percent changes in the instrument price, with a cumulative log-scale chart and CSV, to compare performance across different historical price levels. A buy-and-hold benchmark is included. Monte Carlo resamples daily equity percentage returns in circular moving blocks (five trading days by default) to produce full daily equity paths. Monte Carlo is a diagnostic, not a forecast.

## LucidFlex evaluation and payout estimates

For NQ, ES, GC, MNQ, MES, and MGC, the runner reports both LucidFlex and LucidPro estimates using the selected account sizes. The default prop simulation uses historical point-move P&L (`points`), which remains meaningful on back-adjusted futures series; `current_notional` is an optional alternative that scales directional percentage returns to the latest dataset price. Fees use the configured fixed commission or percentage-per-side model. Positions that would remain open past 4:45 PM ET are closed at the preceding available bar close. LucidPro includes the optional daily loss limit setting, account-specific max size, EOD trailing max-loss lock, evaluation target, payout consistency, buffer and payout amounts. When DLL is enabled, daily P&L is aggregated, so the simulation approximates the soft lock by capping that day's losses at the limit. This is an estimate, not a guarantee; check Lucid's current rules and holiday schedules.

BTC runs a separate synthetic crypto-prop evaluation using clean rounded rule percentages: a 10% profit target, 5% maximum loss, and 3% daily loss, applied to $5K, $10K, $25K, $50K, and $100K account sizes. The starting values came from averaging published rules from HyroTrader, CoinProp, and PropDAO, then rounding to whole percentages for a simple benchmark. It uses BTC trade P&L net of the configured fees and slippage, UTC calendar days, and Monte Carlo resampling. Its daily drawdown check uses net closed P&L and cannot reconstruct intraday floating equity from the trade list; firm-specific trailing, consistency, and minimum-day rules are not represented. Treat this as a comparative research model, not as any firm's actual account rules.

At startup, `NumContracts` can override strategy entry sizes from the prompt or `--num-contracts`; fractional sizes such as `0.1` are supported. Trade P&L, commissions, slippage impact, and position value scale with quantity. PowerLanguage stop amounts retain their platform semantics: `SetStopPosition` (the default) is a dollar amount for the whole position, while `SetStopContract` is an amount per contract. Exit orders close the open simulated position. Equity charts use currency-formatted axes to keep large balances readable.

LucidFlex requires positions flat by 4:45 PM ET and trading resumes at 6:00 PM ET. The local `VideoOVNRangeBreakoutV2.pl` and `VideoOVNRangeBreakout_ORB.pl` files contain separate overnight/opening-range versions; review their strategy code and session assumptions before applying LucidFlex constraints. See Lucid's current [allowed trading times](https://support.lucidtrading.com/en/articles/11404729-allowed-trading-times).

## Data notes

Sixteen years of minute bars can exceed memory limits in CSV form. Parquet is recommended for storage; the initial interpreter processes bars sequentially and is intended as a transparent research prototype. Ensure your source data has consistent session conventions, timestamps, contract rolls, and missing-bar handling. Do not concatenate futures contracts without accounting for roll adjustments.

The OrderFlowBridge bundle supplied for NQ is in `data/OFB/` on this PC. Choose that directory explicitly to use its 1-minute bars. UpVol/DownVol feed the engine's order-flow fields. The binary profile and COT files have selective readers; see [OFB_DATA_GUIDE.md](OFB_DATA_GUIDE.md) for supported Bridge helper calls, time alignment, coverage, and the still-opaque depth/GEX ladder layouts. Market-data files are excluded from Git by design.

## Compatibility boundary and included scripts

The local runner accepts a PowerLanguage `.pl` file path.

The interpreter handles common strategy syntax such as `Once`, bounded `For`
`To`/`DownTo` loops, `IntraBarPersist` declarations, wrapped conditions/expressions, variable
and price history references, `Mod`, `DayOfWeek`, `DateToJulian`, instrument
tick constants, and diagnostic `Print` statements. `Print` calls are no-ops.
`Ticks` maps to input bar `Volume`; this is not a true tick-count series.
Matching bar interval, session timezone, and session hours is necessary for
results to match MultiCharts.

This is not MultiCharts' compiler or execution engine. It supports a growing
subset of single-instrument historical bar strategies and reports unsupported
constructs rather than guaranteeing arbitrary scripts run unchanged. It does
not support arbitrary user-defined functions, portfolio/multi-symbol strategies,
tick-by-tick IOG, full historical DOM/L3 queue replay, or interactive chart UI effects.
The OFB helper subset documented in `OFB_DATA_GUIDE.md` is implemented against the supplied local feed; it does not load or run the vendor DLL. OHLC execution cannot reproduce the
intrabar event order and fill model of MultiCharts. See MultiCharts' official
[PowerLanguage and EasyLanguage overview](https://www.multicharts.com/trading-software/index.php?title=How_to_Learn_PowerLanguage)
and [array documentation](https://www.multicharts.com/trading-software/index.php?title=Array)
for the platform behavior this subset is based on.
